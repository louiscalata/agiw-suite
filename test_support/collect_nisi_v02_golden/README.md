# Collector golden corpus

`cases.json` records 608 deterministic inputs and their complete observed
outputs from the pinned, unmodified `nisi_v02.collect_nisi_v02`: 304 commit
receipt cases and 304 generation receipt cases. Expectations include returned
snapshot/source rows, escaping exception types and messages, and ordered
module-global helper calls and arguments. These characterize current behavior,
including partially populated snapshots after late evidence failures.

Every expectation is generated by executing the original source. None is
written by hand. `generated_from` identifies the source revision and SHA-256.
`generate.py` reads that pristine Git blob, checks its digest and equality with
the working source, and imports a temporary copy to capture the observations.

`support.py` creates a fresh temporary home for each input. Runtime, archive,
receipt, package, and host files are synthetic. Ownership, byte limits, hashes,
JSON parsing, timestamps, symlinks, and relative-file checks use the original
helpers. Explicit fault inputs patch only the named module-global seam.
`Path.home` stays inside the fixture, directory enumeration is sorted, candidate
receipt modification times are explicit, and child-process creation is blocked.

Temporary home prefixes become `<lane folder>` in recorded arguments. Byte
arguments retain a length and digest after replacing the home prefix. Padded
JSON uses canonical trailing whitespace that preserves its total byte length,
so different temporary-directory prefix lengths give identical events.

Exception types always remain part of the contract. A message is compared only when the innermost traceback frame belongs to the module under test and its instruction is an explicit `raise` (`RAISE_VARARGS`); see `test_support/exception_outcome.py`. Interpreter-owned wording, which differs between Python 3.9 and 3.14, is compared by type only. This covers the datetime year-range wording of `now_year_overflow` and the
Path constructor wording of `home_integer`, `home_list`, and `home_bool`.
Application-owned messages raised by the collector, and injected fault messages, remain exact.

The corpus retains all original 602 inputs and adds these refusal witnesses:

| Input | Expected observation |
| --- | --- |
| Commit receipt with `generation` equal to `""`, `0`, or `false` | Source state `error`, runtime integrity `UNKNOWN`, snapshot generation `null`, 12 helper events. |
| Commit manifest `archiveSha256` and receipt `runtimeArchiveSha256` both equal to `"xyz"` | 18 events ending with `_json_bytes`, `_when`; refusal precedes archive hashing, byte reads, and ownership checks. |
| Manifest `files/package.json` equal to the 64-digit integer consisting of ones | 21 events in commit mode and 17 in generation mode; refusal precedes the package-file path and hash helpers. |

The two focused modules are `test_collect_nisi_v02_golden` and
`test_collect_nisi_v02_generation_golden`. The existing `test_nisi_v02` module
remains unchanged. Run these commands from the repository root with a private
`TMPDIR` and Python bytecode writes disabled:

```sh
python3 -B -m unittest -q test_collect_nisi_v02_golden test_collect_nisi_v02_generation_golden
python3 -B -m unittest -q test_nisi_v02
python3 -B -m test_support.collect_nisi_v02_golden.generate --output "$TMPDIR/nisi-cases.json"
python3 -B -m test_support.collect_nisi_v02_golden.mutate --output "$TMPDIR/nisi-mutation.json"
python3 -B -m test_support.collect_nisi_v02_golden.audit --output "$TMPDIR/nisi-audit.json"
```

Use repeated `--compare-python EXECUTABLE` arguments on the generator to require
byte-identical captures from other installed interpreters. `mutate.py --list`
prints the exact mutation catalog. Mutations run only in memory; every kill
must reproduce through the corresponding golden unittest. The audit compares
the pristine source, current source, and corpus, and records original-source
line tracing separately from its diagnostic AST branch probes.

Four diagnostic outcomes are unreachable with the unchanged globals and real
JSON dictionaries: the false lower pin-count comparison in each manifest arm,
an empty runtime-pin loop after the required-file subset check, and an empty
loop over the fixed nonempty host mapping.

The function refuses oversized evidence through helper limits; it contains no
truncation operation. The corpus includes equal and neighboring byte limits,
pin-count limits, timestamp boundaries, malformed and truncated JSON, odd types,
hostile file names, receipt selection ties, drift ordering, early returns, and
caught and escaping exception paths. This is source characterization only.
The existing `roadmap.md` remains the canonical project plan.
